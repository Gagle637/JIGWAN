# 지관(地官) 서비스 기획서

Oct 16, 2026 · @준호

구현 상세(위성 전처리, 결과 카탈로그, 백필, 배치 운영, API 스키마, 비기능 요구사항)는 기술 명세 탭에 있다.

## 1. 서비스 개요

지관(地官)은 지도에서 건물 하나를 클릭하면, 미리 분석해 둔 위성 결과에서 그 건물 주변만 잘라 공공 부동산 데이터·안전 정보와 함께 보여주는 웹 서비스다. 사용자는 원할 때 AI 입지 리포트를 요청해 기본 템플릿으로 받거나 자기 질문을 더한 맞춤 리포트를 받고, 관심 건물에 즐겨찾기·메모를 남겨 지도에서 바로 구분할 수 있다. 위성 분석은 스케줄러가 대상 지역 전체에 대해 미리 실행해 결과를 날짜·범위와 함께 저장하며, 분석 단위는 건물 폴리곤과 그 둘레 500m·1km 반경이다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 지관(地官, JIGWAN) — AI 기반 프롭테크 GIS 입지 분석 플랫폼 |
| 이름의 뜻 | 조선 시대에 풍수로 집터와 묘자리를 골라주던 관리. 위성과 데이터로 터의 입지를 읽어준다는 뜻을 담았다 |
| 한 줄 정의 | “건물을 누르면, 그 동네를 위성과 데이터로 읽어주는 AI 입지 리포트” |
| 서비스 목적 | 흩어져 있는 입지 정보(녹지·개발 변화·건물 스펙·실거래가·안전)를 한 화면에 융합하고, LLM이 자연어로 해석해 준다 |
| 1차 타겟 | 실거주 예정자(전월세·매수 후보 비교), 개인 부동산 투자자 |
| 2차 타겟 | 프롭테크 분석가, 중개사, GIS 서비스 이용자 |
| 서비스 형태 | 반응형 웹(데스크톱 우선), 포트폴리오 겸 MVP → 확장 가능한 구조 |

핵심 가치 제안은 네 가지다.

1. **건물 단위 정밀 타겟팅**: 주소 검색이나 클릭 한 번으로 분석 대상과 분석 영역이 정해지고, 주변 지표가 바로 계산된다.
2. **위성 + 공공데이터 융합**: 부동산 앱이 보여주지 않는 ‘주변 녹지가 늘고 있는가, 근처에서 땅을 파고 있는가’를 위성 픽셀로 수치화한다.
3. **요청형 AI 해석**: 기본 템플릿 리포트로 실거주·투자 관점의 요약을 주고, 사용자가 자기 질문을 더해 맞춤 분석을 받을 수 있다.
4. **나만의 관심 건물 관리**: 즐겨찾기를 폴더로 묶어 관리하고, 즐겨찾기·메모를 남긴 건물은 지도에서 색상과 라벨로 구분되고, 건물마다 여러 리포트를 쌓아 비교할 수 있다.

## 2. 문제 정의와 차별점

기존 부동산 앱은 가격·단지 정보에 강하지만, ‘이 건물 주변 환경이 어떻게 변하고 있는가’는 보여주지 못한다. 지관은 이 빈칸을 위성 시계열과 LLM 해석으로 채운다.

| 사용자 문제 | 현재 방식 | 지관의 해법 |
| --- | --- | --- |
| 정보가 여러 사이트에 흩어져 있음 | 세움터(건축물대장), 실거래가 앱, 생활안전지도, 포털 뉴스를 각각 조회 | 건물 클릭 한 번으로 한 패널에 통합 |
| 주변 환경 변화를 알 수 없음 | 현장 임장, 로드뷰(갱신 주기 불규칙) | Sentinel-2 시계열로 녹지율·개발 변화를 수치화 |
| 데이터를 봐도 해석이 어려움 | 용적률, NDVI 같은 용어를 사용자가 직접 해석 | LLM이 실거주·투자 관점으로 풀어서 설명 |
| 분석 범위가 모호함 | 행정동·시군구 단위 통계 | 건물 중심 500m·1km 버퍼 단위 분석 |

포트폴리오 관점의 차별점은 ‘웹 개발 + 공간 DB + 래스터 연산 + LLM’을 하나의 사용자 시나리오로 엮었다는 점이다. 단순 시각화 뷰어가 아니라, 입력(클릭)부터 출력(리포트)까지 완결된 파이프라인을 보여준다.

## 3. 기능 범위

MVP는 사용자 기능 여섯 가지(F1–F6)와 이를 받치는 위성 분석 배치(F0)로 고정한다. 위성 분석 아이디어 15개와 뉴스 연동은 ‘건물 1km 반경에서 의미 있는 해상도인가’와 ‘입지 판단에 쓰이는가’를 기준으로 단계를 나눴다.

### 3-1. MVP 핵심 기능 (F0–F6)

| ID | 기능 | 사용자가 얻는 것 | 완료 기준 |
| --- | --- | --- | --- |
| F0 | 위성 분석 배치 | 위성 분석 결과(지수·녹지·변화 래스터)가 날짜·범위별로 미리 준비됨 | 스케줄 자동 실행, 대전 전역의 계절별 결과가 카탈로그에 등록됨 |
| F1 | 건물 풋프린트 지도 탐색 | 건물 클릭 또는 주소 검색으로 대상 특정, 500m·1km 버퍼 표시, 분석·안전 레이어 겹쳐 보기 | 클릭 후 1초 이내 하이라이트·버퍼 표시 |
| F2 | 주변 녹지 분석 | 버퍼 내 녹지율(%), 시·구 평균 대비, 3개년 계절별 추이 | NDVI 시계열 차트 + 녹지 마스크 오버레이 |
| F3 | 주변 개발 변화 감지 | 최근 1–3년 토공사·신축 등 지표 변화 구역과 면적 | 변화 폴리곤 + Before/After 비교 |
| F4 | 건물 스펙·시세·안전 | 건축물대장 요약, 인근 실거래 추이, 범죄주의구간 등급 | 3개 카드 + 실거래가 차트 |
| F5 | AI 입지 리포트 (gpt-oss) | 요청 시 생성: 기본 템플릿(3줄 요약, 실거주·투자 총평) → 원하면 자기 질문을 더한 맞춤 분석. 건물당 여러 리포트 보관 | 사용자별 저장·목록 조회, 모든 주장에 수치 출처 표기 |
| F6 | 즐겨찾기·메모 | 관심 건물 즐겨찾기를 폴더(트리)로 묶어 관리, 메모·짧은 라벨·색상 지정 → 지도에서 색상 변경·라벨 표시 | 로그인 사용자별 저장, 저장 즉시 지도에 반영, 폴더 단위 지도 표시 켜기·끄기 |

### 3-2. 확장 분석 모듈 분류

| 분석 모듈 | 데이터(해상도) | 단계 | 입지 분석에서의 쓰임 / 판단 근거 |
| --- | --- | --- | --- |
| NDVI 녹지 시계열 | Sentinel-2 (10m) | MVP | 주거 쾌적성 핵심 지표 |
| NDBI 개발 변화 감지 | Sentinel-2 (20m) | MVP | 호재·공사 소음 징후 |
| 지역 뉴스 키워드 연동 | 네이버 검색 API(뉴스) | 추가개발(보류) | 개발 변화의 맥락 보강, 리포트 입력에 뉴스 제목 추가 |
| 불투수면 비율 | Sentinel-2 (10–20m) | 2단계 | 도시화 수준, 녹지율과 쌍으로 표시 |
| 도로·교통 인프라 공정 | Sentinel-2 + 노선 벡터 | 2단계 | 인근 신규 도로·역세권 호재 추적 |
| 침수 이력(홍수 마스킹) | Sentinel-1 SAR (10m) | 2단계 | 장마철 침수 리스크, 구름 영향 없음 |
| 수계·하천 조망(NDWI/MNDWI) | Sentinel-2 (10–20m) | 2단계 | 수변 조망 여부, 침수와 묶어 ‘물 환경’ 카드 |
| 도시 열섬(LST) | Sentinel-3 SLSTR (1km) | 3단계 | 1km 픽셀은 버퍼 1–4개 수준 → 건물 단위는 Landsat 8/9 열적외(100m) 검토 |
| 대기오염(NO₂ 등) | Sentinel-5P (수 km) | 3단계 | 시·구 단위 참고 지표로만 사용 |
| 산불(NBR)·습지·녹조·해안선·기름유출·선박 탐지 | Sentinel-1/2 | 범위 외 | 도심 건물 입지와 관련 낮음 → 별도 ‘환경 모니터링’ 데모 페이지로 분리 가능 |

제외 항목은 버리지 않는다. 같은 래스터 파이프라인(검색 → 클리핑 → 지수 연산 → 타일)을 재사용하므로, 탐색 없이 AOI를 직접 그리는 ‘환경 분석 랩’ 탭으로 나중에 묶을 수 있다.

## 4. 데이터 소스 명세

모든 데이터는 스케줄러가 정해진 주기로 미리 수집해 DB에 적재하며, 사용자 조회 시 분석용 외부 API를 호출하지 않는다(배경지도와 외부 WMS 레이어 타일만 실시간 중계). 데이터는 PNU(19자리 필지고유번호)와 건물 좌표로 묶인다. PNU에서 법정동코드·본번·부번을 분해해 건축물대장을, 시군구코드(앞 5자리)로 실거래가를 연결한다.

| 구분 | 데이터 항목 | 출처 / 수집 방식 | 연결 키 | 수집 주기(스케줄) |
| --- | --- | --- | --- | --- |
| 위성 | Sentinel-2 L2A(광학, 10–20m), Sentinel-1 GRD(SAR, 2단계) | CDSE STAC API 검색 → 대상 지역 범위만 COG로 잘라 아카이브 | 지역 범위, MGRS 타일 | 5일(재방문 주기)마다 신규 장면 수집, 계절 종료 후 합성 |
| 건물 풋프린트 | 건물 폴리곤 175,270동 + 건축물대장 표제부 속성(용도·면적·사용승인일·층수 등) | 브이월드 GIS건물통합정보(AL\_D010) 대전 파일(EPSG:5186, CP949, 확보 완료 → PostGIS 적재 | PNU, 건물 ID | 분기 1회 |
| 건축물대장 | 용도, 대지면적, 연면적, 건폐율, 용적률, 사용승인일, 세대수 | MVP는 GIS건물통합정보에 붙은 속성 사용. 세대수·총괄표제부가 필요하면 2단계에 세움터 파일 추가 | 시군구·법정동 코드 + 번·지 | 건물 파일과 함께 분기 1회 |
| 실거래가 | 아파트·오피스텔·연립다세대·단독다가구 매매 및 전월세 | 공공데이터포털 국토부 실거래가 API | 시군구코드 + 계약월, 지번으로 PNU 매칭 | 일 1회(당월·전월 재수집) |
| 생활안전 | 범죄주의구간(전체) 밀도 구역별 등급 GRAD(10단계, 경찰청 밀도분석) | 생활안전지도 WMS GetFeatureInfo(2km 구역 단위 호출 → 밀도 구역 geometry 저장) | 밀도 구역 geometry | 연 1회 |
| 베이스맵·경계 | 배경지도, 시군구·법정동 경계 | OSM 타일(MVP), 브이월드 법정구역정보(AL\_D001: 시군구·읍면동 SHP, 시도는 시군구를 합쳐 생성, 법정동 코드 기준. SGIS 행정동 경계는 코드 체계가 달라 쓰지 않음) | 행정구역 코드 | 배경지도는 실시간 타일, 경계는 연 1회 적재 |

지역 뉴스(네이버 검색 API)는 추가개발로 보류해 MVP 데이터 소스에서 뺐다. 데이터 수집에서 정한 원칙은 세 가지다.

- 위성은 STAC(pystac-client)로 검색하고 CDSE S3 키로 다운로드한다. 대전을 덮는 Sentinel-2 타일은 검색 결과의 타일 코드로 확인하고, 두 타일에 걸치면 같은 날짜 장면을 합쳐 쓴다.
- 대량 데이터(건물 폴리곤과 건축물대장 속성, 행정경계)는 API 대신 파일로 받아 적재해 호출 한도 문제를 피한다. API는 실거래와 범죄주의구간에만 쓴다.
- 범죄주의구간 GetFeatureInfo는 밀도 구역 geometry 포함, EPSG:3857 지원, 이용 조건을 확인했다(기술 명세 8-3). 공식 게이트웨이는 GetFeatureInfo를 막아둬서, 수집은 지도 화면이 쓰는 내부 GeoServer 주소로 한다(비공식 경로라 바뀌거나 막힐 수 있음). 배경지도는 MVP에서 OSM을 쓴다.

## 5. 분석 방법론: 사전 분석과 조회 시 계산

위성 분석은 스케줄러가 대전 전역에 대해 미리 돌려, 결과 래스터를 날짜·범위(bbox)와 함께 결과 카탈로그에 저장한다. 사용자가 건물을 고르면 백엔드가 카탈로그에서 필요한 날짜·범위의 결과를 찾아 건물 반경만 잘라 지표를 계산한다. 건물별 결과는 미리 만들지 않는다.

### 5-1. 위성 분석 배치(사전 실행)

| 잡 | 실행 시점 | 처리 내용 | 결과 |
| --- | --- | --- | --- |
| 위성 수집 | 5일마다 | STAC로 신규 L2A 장면 검색, 구름 30% 이하만 대전 범위로 잘라 COG 저장 | `satellite_scene`, 장면 COG |
| 계절 합성 | 분기 1회(계절 종료 후) | SCL 마스킹 → 계절 중앙값 → NDVI·NDBI·녹지 마스크·트루컬러 | 결과 COG + 카탈로그 등록 |
| 변화 분석 | 합성 직후 | 같은 계절 1·2·3년 전 대비 ΔNDBI·ΔNDVI → 변화 마스크와 변화 폴리곤 | 변화 COG + `change_area` + 카탈로그 등록 |
| 지역 기준선 | 합성 직후 | 구·시 단위 평균 녹지율 | `region_stat` |
| 공공데이터 동기화 | 실거래 일 1회, 범죄주의구간 연 1회 | 실거래·범죄주의구간 API 호출, 지번 → PNU 매칭 | `trade`, `crime_segment` |

모든 결과 래스터는 `raster_product`(결과 카탈로그)에 종류·기간·bbox·알고리즘 버전·COG 경로로 등록한다. 잡은 수집 → 합성 → 변화·기준선 순서로 체이닝하고, 각 실행을 `index_run`에 기록해 실패하면 그 단계부터 다시 돌린다.

### 5-2. 조회 시 반경 계산

1. 건물 폴리곤(EPSG:4326)을 geography로 바꿔 `ST_Buffer`로 500m·1km 반경을 만든다.
2. 카탈로그에서 반경과 bbox가 겹치고 필요한 기간(최신 계절 + 최근 3년 13개 계절)에 해당하는 결과를 검색한다.
3. 각 COG에서 반경 범위만 창 읽기(rasterio)하고, 반경 밖·nodata 픽셀을 빼고 통계를 낸다.
4. 실거래·건축물대장·범죄주의 밀도 구역은 DB에서 반경으로 조회한다.
5. 결과는 (건물, 반경, 사용한 카탈로그 버전)을 키로 캐시한다. 새 계절 결과가 등록되면 키가 바뀌어 자동으로 다시 계산된다.

읽기 속도는 P2에서 측정해 목표(수치 2초 이내)를 확인한다.

### 5-3. 주변 녹지 지표 (F2)

```latex
\mathrm{NDVI} = \frac{B8_{NIR} - B4_{Red}}{B8_{NIR} + B4_{Red}}
```

- **배치**: 계절 합성 잡이 SCL로 구름·그림자·권운을 지운 뒤 계절 중앙값 NDVI와 녹지 마스크(NDVI ≥ 0.4, 검증 후 조정)를 만든다.
- **조회**: 반경 안 녹지 픽셀 수 ÷ 유효 픽셀 수 = 녹지율. 13개 계절에 같은 계산을 해 시계열을 만들고, 시·구 평균은 `region_stat`에서 가져온다.
- 유효 픽셀이 반경의 50% 미만인 계절은 `insufficient_data`로 표시한다.

산출물: 반경별 녹지율, 시·구 평균 대비 차이(%p), 3개년 계절별 시계열, 녹지 마스크 레이어, 위성 촬영 기준 기간.

### 5-4. 주변 개발 변화 감지 (F3)

```latex
\mathrm{NDBI} = \frac{B11_{SWIR} - B8_{NIR}}{B11_{SWIR} + B8_{NIR}}
```

- **배치**: 최신 계절과 1·2·3년 전 **같은 계절** 합성을 비교해 ΔNDBI가 상승하고 ΔNDVI가 하락한 픽셀을 ‘개발 후보’로 두고, 0.1ha(약 10픽셀) 미만을 지운 뒤 대전 전역의 변화 폴리곤을 `change_area`에 저장한다.
- **조회**: 반경과 겹치는 변화 폴리곤을 검색해 면적·건물까지 거리·변화 시기를 집계한다. Before/After는 두 시점의 트루컬러 합성 COG를 타일로 보여준다.

산출물: 변화 구역 GeoJSON, 반경 내 총 변화 면적(㎡), 가장 큰 변화 구역 3곳, Before/After 타일 경로.

### 5-5. 건물 스펙·시세 (F4)

GIS건물통합정보에 붙은 건축물대장 속성에서 용도, 대지면적, 연면적, 건폐율, 용적률, 사용승인일(→ 연식), 층수를 정리한다. 속성이 없는 약 30%의 건물(부속·미등재 등)은 ‘대장 정보 없음’으로 표시한다. 실거래는 조회 시 최근 24개월, 같은 주택 유형, 반경 500m 내 거래를 DB에서 모아 월별 ㎡당 단가 중앙값과 거래 건수를 낸다.

### 5-6. 범죄 안전 진단 (F4)

생활안전지도 범죄주의구간(전체)의 밀도 구역별 등급(GRAD, 10단계)을 연 1회 수집해 밀도 구역 geometry와 함께 저장해 두고, 조회 시 반경과 겹치는 구역으로 최고 등급·주의구역 면적·고등급 비중·건물 인접 등급을 구한다. 지도에는 같은 데이터를 WMS 레이어로 겹쳐 보여준다. 등급은 1(낮음)\~10(높음)이며, 높을수록 과거 발생 밀도가 높았다는 뜻일 뿐 현재 위험을 뜻하지 않으므로 ‘위험’ 표현은 쓰지 않는다. 주의구간이 없는 곳은 ‘주의구간 미지정’으로 표현하고 데이터 기간(최근 1년)을 함께 적는다. 교통·화재 등 다른 안전 지표는 MVP에서 제외한다.

### 5-7. AI 입지 리포트 (F5, gpt-oss)

리포트는 OpenAI의 오픈 웨이트 모델 gpt-oss를 자체 서버에서 돌려 만든다. gpt-oss-20b는 16GB 메모리 안에서, gpt-oss-120b는 80GB GPU 1장에서 돌아간다([gpt-oss](https://pypi.org/project/gpt-oss/)). vLLM으로 서빙하면 OpenAI 호환 API로 호출할 수 있다([vLLM 서빙 가이드](https://developers.openai.com/cookbook/articles/gpt-oss/run-vllm)).

- **생성 시점**: 사용자가 요청할 때만 만들고 사용자별로 저장한다. 건물을 조회해도 리포트는 자동으로 만들지 않는다.
- **두 가지 형태**: 먼저 정해진 항목(3줄 요약, 실거주·투자 총평, 리스크)의 기본 템플릿 리포트를 제공하고, 사용자가 원하면 자기 프롬프트(질문·관점)를 더한 맞춤 리포트를 만든다.
- **여러 리포트 보관**: 한 건물에 여러 리포트를 둘 수 있고, 각 리포트는 생성 당시의 입력 데이터와 프롬프트를 함께 보관한다. 다시 만들면 기존 리포트를 고치지 않고 새 리포트로 쌓인다.
- **모델 선택**: 20b를 기본으로 하고, 샘플 50건을 120b와 비교해 한국어 품질 차이가 크면 교체한다.
- **입력과 안전 규칙**: 5-3\~5-6의 반경 결과 JSON(맞춤 리포트는 사용자 프롬프트 추가)만 넣고, 입력에 없는 수치나 사실은 쓰지 않는다. 사용자 프롬프트로도 매수·매도 권유와 ‘위험’ 단정 금지, 근거 키 검증 규칙은 바뀌지 않는다.
- **문체·고지**: 한국어 예시 리포트(few-shot)와 용어 사전을 고정하고, 화면에는 ‘투자 자문이 아닌 참고 정보’ 고지와 데이터 기준일을 둔다.

## 6. 시스템 아키텍처와 기술 스택

## 7. 데이터 플로우와 사용자 여정

데이터 흐름은 배치 경로(A)와 조회 경로(B)로 나뉜다. 배치는 위성 분석 결과를 날짜·범위와 함께 쌓아두고, 사용자의 클릭이 들어오면 그 결과에서 건물 반경만 잘라 계산한다.

카탈로그에 해당 범위·기간의 결과가 없으면 그 항목만 ‘데이터 없음’으로 응답한다. 리포트는 건물 조회와 별개로, 사용자가 요청할 때만 gpt-oss가 만들어 사용자별로 저장한다.

| `region` | region\_code(PK: 시도 2자리·시군구 5자리·법정동 10자리), level(sido·sigungu·bjd), name, parent\_code(자기 참조), geom(MultiPolygon, 4326), source\_date | 행정경계 적재(buildings 앱) |
| `service_area` | sido\_code(PK), name, enabled, grid(EPSG:32652), bbox(4326), added\_at | 서비스 지역 목록(core 앱, areas 명령). 기술 명세 11장 |

반경 계산 결과는 (건물, 반경, 사용한 `raster_product` id 목록)을 키로 캐시해 사용자 간에 공유한다. 리포트는 사용자별로 따로 만들고, 생성 당시의 입력(`input_snapshot`)과 프롬프트를 함께 저장해 나중에 데이터가 갱신돼도 어떤 데이터로 만든 리포트인지 추적할 수 있게 한다.

## 11. 기대 효과와 성공 지표

이 프로젝트는 ‘대용량 지리공간 파이프라인 + LLM’을 하나의 제품 시나리오로 완성했음을 수치로 증명하는 것을 목표로 한다.

- **기술적 깊이**: 벡터(PostGIS)·래스터(Rasterio/TiTiler)·스케줄 배치(Celery Beat)·자체 서빙 LLM(gpt-oss)을 ‘사전 분석 + 조회 시 계산’ 구조로 연결한 설계 역량을 보여준다.
- **실무적 효용**: 혼자 하면 여러 사이트를 돌아야 하는 입지 조사를 클릭 한 번, 수 초 안으로 줄인다.
- **확장성**: 결과 카탈로그에 새 지수 래스터를 등록하면 조회 로직을 크게 바꾸지 않고 새 지표를 붙일 수 있고, 지역만 늘리면 커버리지를 넓힐 수 있다.

| 지표 | 목표(MVP) | 측정 방법 |
| --- | --- | --- |
| 건물 클릭 → 수치 표시 | 2초 이내 | `insight` 응답 시간 p90 |
| 리포트 생성 | 30초 이내(기본 템플릿 기준) | 생성 요청–완료 시간 p90 |
| 결과 카탈로그 커버리지 | 대전 전역, 13개 계절 100% | 계절별 결과 bbox가 대전 경계를 덮는지 확인 |
| 배치 1회 처리 시간(대전 전체) | P2에서 측정 후 확정 | `index_run` 시작–종료 시간 |
| 개발 변화 감지 정밀도 | 80% 이상 | 알려진 공사 현장 30곳 수작업 검증 |
| 실거래가 건물 매칭률 | 아파트 95%, 오피스텔·연립 90%(단독·다가구 제외) | 매칭 성공 건수 / 전체 거래 건수 |
| 리포트 근거 오류 | 0건 | 근거 키 자동 검증 + 샘플 50건 검토 |
